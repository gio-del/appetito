# Gateway on the server — context for Claude

This folder (`~/projects`) is the server's Gateway, not a project: see `CONTEXT.md` for its terms and `GATEWAY.md` for the snapshot of every Project. Each Project is an independent Git repo in its own subfolder. Installed and kept by the home-server repo (`device/edge/debian/gateway/`, `gateway-sync`): edit there and deploy, not here.

- **home-server is a Project too**: `home-server` here is a link to `~/home-server`, the repo that runs this machine (its own `CLAUDE.md`, issues in `issues/`). The other Projects are listed in its `device/edge/debian/projects` (installed as `/etc/hs-projects`): adding a Project = a line there + deploy; `gateway-sync` clones it here.
- **A Project can have an app on this server** (column `app service` of that file): a runit service with its own `<service>-setup` script in home-server, a Caddy site in 8446-8459 (owner devices only) and a card in the dashboard group "Progetti". The app is installed from a pinned commit of the Project, never from this working copy, so editing a Project here does not change what runs until its pin is bumped in home-server and deployed.
- **Before working on a Project, read that Project's own `CLAUDE.md`** and follow its process (home-server: `issues/`; Sumisura: GitHub issues and PRs).
- **Scripts only fast-forward** a clean Project (`gateway-sync`, hourly; the reason it did not shows in `GATEWAY.md`), never check out or reset, and app builds read the pinned commit with `git fetch` + `git archive`. Work on a branch, commit, and publish it on the Project's remote: nothing stays only on the Edge.
- `GATEWAY.md` is a snapshot kept by `gateway-sync` (deploy + hourly): one row per Project with its Status from the list, Checkpoint = the HEAD of its folder here and that commit's date. It rewrites only those rows; anything else in the file (per-Project notes) is left alone.
- **Daily proposals** (`ops-suggest`): every Project whose line in the list has an issues dir (column 5, rules file in column 6). They go to home-server's tracker, so today only home-server has one; Projects tracked elsewhere (Sumisura: GitHub Issues) wait for home-server issue 091.
- The ops session has sudo: a Project's content is trusted only as far as its repo is the owner's. Don't run a Project's build or tests in the ops session by hand; the app setup builds as the app's own unprivileged user.

- **Interfaccia** (owner, issue 499): ogni modifica a come una cosa appare o si usa passa dalla skill di design fissata: leggi `/usr/local/share/hs-skills/ui-ux-pro-max/SKILL.md` e interrogala con `python3 -I /usr/local/share/hs-skills/ui-ux-pro-max/scripts/search.py "<query>" --design-system` (o `--domain <d>`; mai `--persist`). Sono consigli: le regole del repo vincono (CSP, dipendenze, lingua dei testi). Nel repo e nella PR non si nomina la skill.
